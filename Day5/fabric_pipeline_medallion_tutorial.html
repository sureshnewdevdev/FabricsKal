Microsoft Fabric Pipeline → Medallion Architecture

Hands-on retail sales workshop | Workspace + Lakehouse + Data Pipeline + PySpark Notebooks + VS Code Copilot

1. End-to-end architecture

Azure Blob CSV source → Fabric Copy Data pipeline → Lakehouse Files/input → Bronze Delta → Silver Delta → Gold Delta

Use one Fabric workspace, one Lakehouse, one Data Pipeline, and three notebooks. GitHub Copilot in VS Code writes and reviews PySpark; Fabric notebooks execute Spark.

For a real pipeline copy demonstration, place the CSV files in a source accessible through a Fabric Copy activity, such as Azure Blob Storage or ADLS Gen2. A local PC folder is not a cloud source connection. If you do not have cloud storage, upload the files to Lakehouse Files/input manually and start with the notebooks; this bypasses the Copy activity.

2. Input data and business rules

Download the accompanying CSV files: sales.csv, products.csv and stores.csv. sales.csv has duplicate sale_id 1010, quantity 0, negative price, missing customer, and unknown store S99. Clean sales must have quantity > 0, price ≥ 0, customer ID present, and matching store/product master.

3. Create workspace, Lakehouse and notebooks

  1. Open Microsoft Fabric and choose a Fabric-enabled workspace.
  2. Select New item → Lakehouse; name it RetailLakehouse.
  3. Open Lakehouse → Files → create input folder.
  4. Create notebooks named 01_Bronze_Ingestion, 02_Silver_Cleansing, 03_Gold_Aggregation.
  5. Attach RetailLakehouse as the default Lakehouse for each notebook.
  6. In VS Code, install GitHub Copilot and Python extensions; use Copilot Chat to draft PySpark and paste reviewed code into the appropriate Fabric notebook.

4. Create pipeline and copy source CSVs

  1. In the workspace select New item → Data pipeline. Name it PL_Retail_Medallion.
  2. Choose Copy data and add a Copy activity named Copy_CSV_to_Lakehouse.
  3. In Source, select your Azure Blob Storage or ADLS Gen2 connection and the folder containing the three CSV files. Authenticate with an authorized connection.
  4. Choose Binary file format to preserve original CSV bytes. Configure source folder and copy pattern to include the three files.
  5. In Destination, select RetailLakehouse, root folder Files, path input, and Binary format. Preserve file names.
  6. Save and run the pipeline. Check Output for a successful Copy activity, then verify the three CSV files under RetailLakehouse → Files → input.

Depending on source and UI version, configure file selection and source/destination paths in the Copy activity's Source and Destination tabs. Avoid selecting Tables for this example because the Bronze notebook is responsible for converting raw files into Delta tables.

5. Notebook 01 — Bronze ingestion

Definition: Bronze preserves source data as raw, queryable Delta tables with ingestion metadata. Read every column as string to avoid discarding malformed values before validation.

from pyspark.sql import functions as F
from pyspark.sql.types import StructType, StructField, StringType

schemas = {
 'sales': ['sale_id','sale_date','store_id','product_id','customer_id','quantity','unit_price'],
 'products': ['product_id','product_name','category'],
 'stores': ['store_id','store_name','city']
}
for name, columns in schemas.items():
    schema = StructType([StructField(c, StringType(), True) for c in columns])
    df = (spark.read.option('header',True).schema(schema)
          .csv(f'Files/input/{name}.csv')
          .withColumn('source_file', F.input_file_name())
          .withColumn('ingestion_timestamp', F.current_timestamp()))
    df.write.format('delta').mode('overwrite').saveAsTable(f'bronze_{name}')
    print(name, spark.table(f'bronze_{name}').count())

For this repeatable full-refresh classroom demo, overwrite Bronze tables. Production incremental ingestion needs a different design (batch IDs, checkpoints, merge/deduplication).

6. Notebook 02 — Silver validation and enrichment

Definition: Silver converts raw strings to typed fields, rejects invalid rows, deduplicates and enriches valid sales with store and product information.

from pyspark.sql import functions as F
from pyspark.sql.window import Window

raw = spark.table('bronze_sales')
products = spark.table('bronze_products').select('product_id','product_name','category')
stores = spark.table('bronze_stores').select('store_id','store_name','city')

sales = (raw.withColumn('sale_date', F.to_date('sale_date','yyyy-MM-dd'))
 .withColumn('quantity',F.col('quantity').cast('int'))
 .withColumn('unit_price',F.col('unit_price').cast('decimal(18,2)')))

# Exact duplicates: keep one copy deterministically for this demo.
sales = sales.dropDuplicates(['sale_id','sale_date','store_id','product_id',
                               'customer_id','quantity','unit_price'])

joined = (sales.join(products,'product_id','left')
               .join(stores,'store_id','left'))
reason = (F.when(F.col('sale_id').isNull(),'missing sale_id')
 .when(F.col('sale_date').isNull(),'invalid date')
 .when(F.col('customer_id').isNull() | (F.trim('customer_id')==''),'missing customer')
 .when(F.col('quantity').isNull() | (F.col('quantity')<=0),'invalid quantity')
 .when(F.col('unit_price').isNull() | (F.col('unit_price')<0),'invalid price')
 .when(F.col('product_name').isNull(),'unknown product')
 .when(F.col('store_name').isNull(),'unknown store'))
joined = joined.withColumn('rejection_reason',reason)

# Reject conflicting sale IDs rather than arbitrarily choosing a record.
counts = joined.groupBy('sale_id').count().withColumnRenamed('count','id_count')
joined = joined.join(counts,'sale_id','left')
joined = joined.withColumn('rejection_reason',
    F.when(F.col('id_count')>1,F.lit('conflicting sale_id'))
     .otherwise(F.col('rejection_reason')))

rejects = joined.filter(F.col('rejection_reason').isNotNull())
valid = (joined.filter(F.col('rejection_reason').isNull())
 .withColumn('revenue', F.col('quantity') * F.col('unit_price'))
 .drop('rejection_reason','id_count'))
rejects.write.format('delta').mode('overwrite').saveAsTable('silver_rejected_sales')
valid.write.format('delta').mode('overwrite').saveAsTable('silver_sales')
print('Valid:',valid.count(),'Rejected:',rejects.count())

Expected: 7 valid unique transactions, 4 invalid unique transactions, plus 1 removed exact duplicate. This notebook stores the 4 invalid unique records in the rejection table; add a separate duplicate audit table if every source row must be reconciled individually.

7. Notebook 03 — Gold reporting

Definition: Gold aggregates trusted Silver data for business analytics and KPI reporting.

from pyspark.sql import functions as F
silver = spark.table('silver_sales')
gold = (silver.groupBy('sale_date','store_id','store_name','city','category')
 .agg(F.count('*').alias('transaction_count'),
      F.sum('quantity').alias('units_sold'),
      F.sum('revenue').alias('total_revenue')))
gold.write.format('delta').mode('overwrite').saveAsTable('gold_daily_sales')
display(spark.table('gold_daily_sales').orderBy('sale_date','store_id'))
print('Total revenue:',gold.agg(F.sum('total_revenue')).first()[0])

8. Add Notebook activities to pipeline

  1. Return to PL_Retail_Medallion and add three Notebook activities.
  2. Rename activities Run_Bronze, Run_Silver, and Run_Gold.
  3. For each activity, select its corresponding Fabric notebook.
  4. Connect Copy_CSV_to_Lakehouse → Run_Bronze → Run_Silver → Run_Gold using On success dependencies.
  5. Save and run the complete pipeline; check the Output tab and notebook run details.
  6. Once validated, use Schedule for a recurring execution if needed.

On-success dependencies prevent downstream transformations from running after an upstream failure. For production, add monitoring, failure notifications, retry settings and operational logs.

10. Engineering best practices

PracticeReason
Raw files firstPreserve original input for audit and replay.
Explicit schemaAvoid inconsistent inference and accidental type coercion.
Reject invalid rowsPrevent incorrect revenue from entering Gold.
Deterministic deduplicationPrevent double counting and unpredictable survivor selection.
Idempotent rerunsA repeated batch should not inflate totals.
Pipeline dependenciesOnly run Silver after Bronze succeeds, and Gold after Silver.
Least privilege and secrets managementKeep credentials out of notebooks and Copilot prompts.
Review Copilot outputAI-generated code may be wrong, insecure or incompatible.
Delta tablesProvide transactional consistency and efficient downstream reads.
Production incremental strategyUse ingestion IDs, watermark/checkpoints and MERGE when replacing full-refresh behavior.

Common troubleshooting

TABLE_OR_VIEW_NOT_FOUND: Attach the same Lakehouse to each notebook and run Bronze first.
Path not found: Confirm Files/input/sales.csv exists and check file-name case.
Copy fails: Test source connection permissions and destination Files path.
Notebook activity fails: Open activity run details; verify notebook selection and Lakehouse attachment.
