Environment & Fabric GUI

  1. Open Microsoft Fabric and sign in to an account with a workspace on active Fabric capacity or trial.
  2. Open Workspaces → create or select a workspace, e.g. RetailMedallionLab.
  3. Within that workspace choose New item → Lakehouse (the wording/location may vary with the Fabric UI). Name it RetailLakehouse.
  4. Open the Lakehouse Explorer → Files → create folder input; upload sales.csv, products.csv, stores.csv into it.
  5. In the same workspace create three Notebook items named 01_bronze_ingest, 02_silver_clean, 03_gold_aggregate.
  6. Open each notebook, set the default language to PySpark (Python), and use Add lakehouse or the Lakehouses explorer to attach RetailLakehouse as the default Lakehouse.
  7. Install VS Code, the Microsoft Python extension and GitHub Copilot extension. Sign in to GitHub Copilot with an eligible account.
  8. Create a local folder retail-fabric-medallion and three .py files. Use Copilot Chat to generate/review code, then paste each file into the corresponding Fabric notebook cell. Run in Bronze → Silver → Gold order.

A normal local Python interpreter cannot run spark without a configured Spark runtime. Use VS Code for authoring; run these notebook cells inside Fabric.

Notebook 01 — Bronze

Purpose: preserve raw string values and ingest each source as a Delta table. Rerun behavior: overwrite is intentional for this small full-snapshot demo.

Paste code into matching Fabric PySpark notebook
from pyspark.sql import functions as F, types as T
# Attach this notebook to the target Lakehouse before running.
base = "Files/input"
sales_schema = T.StructType([
    T.StructField("sale_id", T.StringType()), T.StructField("sale_date", T.StringType()),
    T.StructField("store_id", T.StringType()), T.StructField("product_id", T.StringType()),
    T.StructField("customer_id", T.StringType()), T.StructField("quantity", T.StringType()),
    T.StructField("unit_price", T.StringType())])
products_schema = T.StructType([T.StructField(x, T.StringType()) for x in ["product_id","product_name","category"]])
stores_schema = T.StructType([T.StructField(x, T.StringType()) for x in ["store_id","store_name","city"]])
for filename, table, schema in [
    ("sales.csv","bronze_sales",sales_schema),
    ("products.csv","bronze_products",products_schema),
    ("stores.csv","bronze_stores",stores_schema)]:
    df = (spark.read.option("header",True).schema(schema).csv(f"{base}/{filename}")
          .withColumn("source_file", F.lit(filename))
          .withColumn("ingested_at", F.current_timestamp()))
    # Full snapshot mode for this workshop: rerunning replaces, never duplicates.
    df.write.format("delta").mode("overwrite").option("overwriteSchema","true").saveAsTable(table)
    print(table, spark.table(table).count())

Notebook 02 — Silver

Purpose: apply quality rules, keep valid records, quarantine invalid records and audit exact duplicates. For duplicate IDs with conflicting data, quarantine all conflicting rows rather than choosing arbitrarily.

Paste code into matching Fabric PySpark notebook
from pyspark.sql import functions as F, Window
from pyspark.sql import types as T
from functools import reduce
raw = spark.table("bronze_sales")
# Exact duplicate handling: one copy retained; a duplicate audit is saved.
source_cols = ["sale_id","sale_date","store_id","product_id","customer_id","quantity","unit_price"]
exact_dupes = raw.groupBy(*source_cols).count().filter("count > 1")
exact_dupes.write.format("delta").mode("overwrite").saveAsTable("silver_exact_duplicates")
unique = raw.dropDuplicates(source_cols)
# Conflicting rows with same sale_id are quarantined, not arbitrarily selected.
conflict_ids = unique.groupBy("sale_id").count().filter("count > 1").select("sale_id")
products = spark.table("bronze_products").select("product_id","product_name","category")
stores = spark.table("bronze_stores").select("store_id","store_name","city")
# Cast and enrich; ensure master keys are unique before joining.
assert products.groupBy("product_id").count().filter("count > 1").count() == 0
assert stores.groupBy("store_id").count().filter("count > 1").count() == 0
prepared = (unique
    .withColumn("parsed_date", F.to_date("sale_date", "yyyy-MM-dd"))
    .withColumn("qty", F.expr("try_cast(quantity as int)"))
    .withColumn("price", F.expr("try_cast(unit_price as decimal(18,2))"))
    .join(products, "product_id", "left")
    .join(stores, "store_id", "left")
    .join(conflict_ids.withColumn("has_conflict", F.lit(True)), "sale_id", "left"))
checks = [
 (F.col("sale_id").isNull() | (F.trim("sale_id") == ""), "missing_sale_id"),
 (F.col("parsed_date").isNull(), "invalid_date"),
 (F.col("customer_id").isNull() | (F.trim("customer_id") == ""), "missing_customer"),
 (F.col("qty").isNull() | (F.col("qty") <= 0), "invalid_quantity"),
 (F.col("price").isNull() | (F.col("price") < 0), "invalid_price"),
 (F.col("product_name").isNull(), "unknown_product"),
 (F.col("store_name").isNull(), "unknown_store"),
 (F.coalesce(F.col("has_conflict"), F.lit(False)), "conflicting_sale_id")]
reason_exprs = [F.when(cond, F.lit(reason)) for cond, reason in checks]
# For compatibility across Spark runtimes, use filter() to remove null elements.
checked = prepared.withColumn("reasons", F.filter(F.array(*reason_exprs), lambda x: x.isNotNull()))
rejected = checked.filter(F.size("reasons") > 0).withColumn("rejection_reason", F.concat_ws(",", "reasons"))
valid = (checked.filter(F.size("reasons") == 0)
    .select("sale_id", F.col("parsed_date").alias("sale_date"), "store_id", "store_name", "city",
            "product_id", "product_name", "category", "customer_id",
            F.col("qty").alias("quantity"), F.col("price").alias("unit_price"))
    .withColumn("revenue", (F.col("quantity") * F.col("unit_price")).cast("decimal(20,2)")))
valid.write.format("delta").mode("overwrite").option("overwriteSchema","true").saveAsTable("silver_sales")
rejected.write.format("delta").mode("overwrite").option("overwriteSchema","true").saveAsTable("silver_rejected_sales")
print("Valid", valid.count(), "Rejected unique records", rejected.count(), "Extra duplicate copies", exact_dupes.agg(F.sum(F.col("count")-1)).first()[0] or 0)

Notebook 03 — Gold

Purpose: aggregate clean sales into business-ready daily store/category metrics and run acceptance assertions.

Paste code into matching Fabric PySpark notebook
from pyspark.sql import functions as F
silver = spark.table("silver_sales")
gold = (silver.groupBy("sale_date", "city", "store_id", "category")
    .agg(F.count("sale_id").alias("transaction_count"),
         F.sum("quantity").alias("units_sold"),
         F.sum("revenue").cast("decimal(20,2)").alias("total_revenue")))
gold.write.format("delta").mode("overwrite").option("overwriteSchema","true").saveAsTable("gold_daily_sales")
display(spark.table("gold_daily_sales").orderBy("sale_date", "city"))
assert silver.count() == 7, "Expected 7 valid sales"
assert float(silver.agg(F.sum("revenue")).first()[0]) == 8050.0, "Revenue mismatch"
assert spark.table("gold_daily_sales").count() == 7, "Expected 7 grouped rows"
print("PASS: 7 valid sales, 7 Gold groups, INR 8050 revenue")

Best practices

  1. Restrict scope: use only one workspace, one Lakehouse and three notebooks for this exercise.
  2. Separate layers: Bronze raw preservation; Silver data quality; Gold business aggregates.
  3. Explicit schema: do not rely on automatic type inference for critical fields.
  4. Deterministic reruns: overwrite the full snapshot in this lab; for production increments, design idempotent MERGE logic and watermarks.
  5. Reject with reasons: never silently discard bad records.
  6. Audit duplicates: distinguish identical duplicate rows from conflicting transaction IDs.
  7. Use decimals for money: avoid floating-point arithmetic for revenue calculations.
  8. Check join cardinality: ensure master product/store IDs are unique before joining.
  9. Test expectations: assert record counts, unique IDs and revenue totals.
  10. Protect data: avoid secrets and real customer PII in prompts or repository files.
  11. Review Copilot code: verify table names, Spark functions, runtime compatibility and SQL logic before execution.
  12. Commit source code: version the local .py files and README in Git; avoid committing credentials or sensitive extracts.
  13. Cost control: stop unused sessions and monitor Fabric capacity usage.
  14. Deployment discipline: manually transfer reviewed code into Fabric notebooks for this workshop; do not assume VS Code automatically publishes them.
