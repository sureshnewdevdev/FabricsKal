STEP 01Start here: what you will build

Build a real Microsoft Fabric Data Factory pipeline from VS Code. First prove authentication with a small Wait pipeline; then orchestrate a PySpark notebook that cleans sales data and publishes Bronze, Silver and Gold Delta tables.

Recommended order: follow lessons 1–17 in order. The Copilot/MCP route and scheduling are optional extensions. Allow 2–3 hours on first setup, including sign-in and Spark startup.

Definition of done: VS Code creates a Fabric pipeline, triggers its real ETL run, monitors a successful terminal state, and you verify 5 Silver rows and ₹54,850.00 total sales in the Lakehouse.
This package contains runnable client code and a notebook. It has been checked offline; it has not been executed against your Fabric tenant. Your account, capacity, consent and connection settings determine remote execution.

STEP 02Understand the architecture

Your Windows laptopVS Code edits JSON, Python and notebook files. The Python client calls Fabric APIs using your signed-in identity.
Fabric Data FactoryThe remote pipeline orchestrates a Wait activity followed by a Notebook activity on success.
Fabric Spark + OneLakeThe notebook reads the CSV, validates records and writes managed Delta tables in the default Lakehouse.

Data path: sales.csv in Lakehouse Files → Bronze raw table → duplicate removal and validation → Silver clean table + rejected records → Gold daily sales.

Data pipelineCoordinates activities and dependenciesFabric service
PySpark notebookPerforms ETL transformationsFabric Spark
LakehouseStores source files and Delta tablesOneLake
Copilot/MCPOptional natural-language tool accessVS Code plus remote Fabric operations

Running fabric_lab.py locally does not turn your laptop into a Fabric Spark cluster. Running the notebook with ordinary local Python will not provide the Fabric spark session.

PowerShell · execute in order
.venv\Scripts\python.exe fabric_lab.py create
.venv\Scripts\python.exe fabric_lab.py run
.venv\Scripts\python.exe fabric_lab.py watch
  1. The create command submits the JSON as a base64 definition part named pipeline-content.json.

Checkpoint: a remote pipeline exists and the smoke job reaches Completed (or the corresponding successful UI state). The two-second Wait does not mean the whole service run takes only two seconds.

STEP 13Walk through the ETL code cell by cell

The supplied notebook has one explanatory Markdown cell and four executable code cells. The code below is complete; no API keys or extra notebook packages are needed.

Code cell 1 · Read CSV and publish Bronze

PySpark · runs in Fabric
from pyspark.sql import functions as F

SOURCE_PATH = "Files/inbound/sales.csv"
BRONZE_TABLE = "lab_bronze_sales"
SILVER_TABLE = "lab_silver_sales"
REJECT_TABLE = "lab_rejected_sales"
GOLD_TABLE = "lab_gold_daily_sales"

raw = spark.read.option("header", True).option("inferSchema", False).csv(SOURCE_PATH)
required = {"order_id", "order_date", "customer_id", "product", "quantity", "unit_price"}
if set(raw.columns) != required:
    raise ValueError(f"Expected exactly these columns: {sorted(required)}")
raw_count = raw.count()
raw.write.format("delta").mode("overwrite").saveAsTable(BRONZE_TABLE)
print(f"Bronze input rows: {raw_count}")
display(raw)

Code cell 2 · Remove duplicates and classify records

PySpark · runs in Fabric
# Remove exact duplicate source rows; conflicting versions are not resolved by this lab.
deduplicated = raw.dropDuplicates(raw.columns)
duplicate_count = raw_count - deduplicated.count()

staged = deduplicated.select(
    F.trim("order_id").alias("order_id"),
    F.col("order_date").alias("order_date_raw"),
    F.expr("try_cast(order_date as date)").alias("order_date"),
    F.trim("customer_id").alias("customer_id"),
    F.trim("product").alias("product"),
    F.expr("try_cast(quantity as int)").alias("quantity"),
    F.expr("try_cast(unit_price as decimal(18,2))").alias("unit_price")
)
blank_order = F.col("order_id").isNull() | (F.col("order_id") == "")
blank_customer = F.col("customer_id").isNull() | (F.col("customer_id") == "")
bad_date = (F.col("order_date").isNull()
            | ~F.coalesce(F.col("order_date_raw").rlike(r"^[0-9]{4}-[0-9]{2}-[0-9]{2}$"), F.lit(False)))
bad_quantity = F.col("quantity").isNull() | (F.col("quantity") <= 0)
bad_price = F.col("unit_price").isNull() | (F.col("unit_price") <= 0)
staged = staged.withColumn("reject_reason", F.concat_ws("; ",
    F.when(blank_order, F.lit("Missing order ID")),
    F.when(blank_customer, F.lit("Missing customer ID")),
    F.when(bad_date, F.lit("Invalid date")),
    F.when(bad_quantity, F.lit("Invalid quantity")),
    F.when(bad_price, F.lit("Invalid unit price"))
))
rejected = staged.filter(F.col("reject_reason") != "")
silver = (staged.filter(F.col("reject_reason") == "")
    .drop("reject_reason", "order_date_raw")
    .withColumn("sales_amount", (F.col("quantity") * F.col("unit_price")).cast("decimal(20,2)")))
# Exact duplicates were removed; any remaining repeated order ID is ambiguous.
if silver.groupBy("order_id").count().filter("count > 1").limit(1).count():
    raise ValueError("Conflicting duplicate order IDs require a business resolution rule")
valid_count, reject_count = silver.count(), rejected.count()
if raw_count != duplicate_count + valid_count + reject_count:
    raise ValueError("Row reconciliation failed")

Code cell 3 · Publish Silver, rejected records and Gold

PySpark · runs in Fabric
gold = silver.groupBy("order_date").agg(
    F.count("*").alias("order_count"),
    F.sum("sales_amount").alias("total_sales")
)
# Full refresh is deliberate for this isolated lab, not a production loading default.
rejected.write.format("delta").mode("overwrite").saveAsTable(REJECT_TABLE)
silver.write.format("delta").mode("overwrite").saveAsTable(SILVER_TABLE)
gold.write.format("delta").mode("overwrite").saveAsTable(GOLD_TABLE)
print(f"Duplicates removed: {duplicate_count}; Silver rows: {valid_count}; Rejected rows: {reject_count}")
display(spark.table(GOLD_TABLE).orderBy("order_date"))

Code cell 4 · Validate the fixed sample

PySpark · runs in Fabric
# Fixed-fixture checks: update these if you intentionally replace the sample CSV.
from decimal import Decimal
assert raw_count == 8
assert duplicate_count == 1
assert valid_count == 5
assert reject_count == 2
assert spark.table(GOLD_TABLE).count() == 3
actual_total = spark.table(GOLD_TABLE).agg(F.sum("total_sales").alias("total")).first()["total"]
assert actual_total == Decimal("54850.00"), f"Unexpected total: {actual_total}"
print("PASS: 8 raw = 1 duplicate + 5 valid + 2 rejected; total INR 54850.00")
Write behavior: this isolated lab deliberately replaces four lab_* tables. Each Delta table write commits separately; a later failure does not roll back earlier writes. This is a repeatable full refresh exercise, not a production incremental loading design.

Amounts use decimal types; input fields are initially strings. Invalid rows retain a reason. Exact duplicate removal is separate from conflicting order IDs, which cause an explicit error rather than an arbitrary winner.

STEP 16Run and monitor the ETL from VS Code

PowerShell · run once, then observe
.venv\Scripts\python.exe fabric_lab.py run
.venv\Scripts\python.exe fabric_lab.py status
.venv\Scripts\python.exe fabric_lab.py watch

Run submits one new job. Status reads that job once. Watch polls it. Repeating run creates another execution; repeating status/watch only observes the saved execution.

API observationMeaningNext action
HTTP 202 AcceptedService accepted the requestPoll its job-instance Location
NotStarted / InProgressQueued or runningWait and inspect capacity if delayed
CompletedThe job finished successfullyVerify tables and notebook checks
FailedExecution failedRead failureReason and activity details
Cancelled / DedupedCancelled or skipped as duplicateInspect run history; do not report success

The script treats definition/create operations separately from pipeline job execution. An operation status of Succeeded proves that the definition request finished; it does not prove a later ETL job ran successfully.

Portal verification

  1. Open the pipeline’s run history/Output or the Fabric monitoring view.
  2. Find the run by ID and timestamp.
  3. Inspect Wait and Notebook activity results.
  4. Open the notebook execution details for the actual output, Spark errors and assertion results.

STEP 21Scheduling, identity and cleanup

Only schedule the lab after a manual run succeeds. In the Fabric pipeline designer, open the schedule controls, select your intended time zone and recurrence, verify the next run, then save/enable it.

Example: choose India Standard Time for 09:00 IST. If a control only accepts UTC, 09:00 IST corresponds to 03:30 UTC. Record the actual configured time zone; do not assume the portal uses the laptop’s zone.

A schedule requires an authorized execution identity/connection, not an open VS Code terminal. Production automation should use an intentionally configured supported identity, approved permissions, operational ownership and monitoring.

Finish the training session

  1. Disable any schedule you created for the exercise.
  2. Stop any still-running interactive Spark session when you finish using the notebook.
  3. Keep source code and expected results; remove only lab resources you intentionally created when no longer needed.
  4. Do not delete shared workspaces/capacities or pause a shared capacity as a routine cleanup step.

The example’s full refresh is appropriate only for its isolated lab tables. Production design needs incremental loading rules, retry/idempotency strategy, conflict handling, publication consistency and secret management.

Python · local REST client
"""Local Fabric REST client. Run from VS Code; compute stays in Fabric."""
import argparse
import base64
import json
import os
from pathlib import Path
import shutil
import subprocess
import time
from urllib.parse import urlparse
from uuid import UUID

import requests

ROOT = Path(__file__).resolve().parent
BASE = "https://api.fabric.microsoft.com/v1"
STATE_FILE = ROOT / ".local" / "state.json"


def load_json(path):
    return json.loads(Path(path).read_text(encoding="utf-8-sig"))


def save_json(path, data):
    path = Path(path)
    path.parent.mkdir(parents=True, exist_ok=True)
    path.write_text(json.dumps(data, indent=2), encoding="utf-8")


def guid(value):
    return str(UUID(value))


class FabricClient:
    def __init__(self):
        az = shutil.which("az")
        if not az:
            raise RuntimeError("Azure CLI not found. Install it, restart VS Code, then az login.")
        args = [az, "account", "get-access-token", "--resource",
                "https://api.fabric.microsoft.com", "--query", "accessToken", "-o", "tsv"]
        result = subprocess.run(args, capture_output=True, text=True, check=False)
        if result.returncode:
            raise RuntimeError("Token acquisition failed. Run az login for the correct tenant. "
                               "Resolve consent/Conditional Access with your admin if required.")
        self.token = result.stdout.strip()
        if not self.token:
            raise RuntimeError("Azure CLI returned no access token")

    def request(self, method, url, body=None):
        if not url.startswith("https://"):
            url = BASE + "/" + url.lstrip("/")
        parsed = urlparse(url)
        if parsed.scheme != "https" or parsed.netloc.lower() != "api.fabric.microsoft.com":
            raise RuntimeError("Refusing to send the Fabric token to another host")
        response = requests.request(method, url, json=body, timeout=(15, 120),
            allow_redirects=False, headers={"Authorization": "Bearer " + self.token})
        if response.status_code >= 400:
            # Never print the Authorization header or token.
            raise RuntimeError(f"Fabric HTTP {response.status_code}; Retry-After="
                f"{response.headers.get('Retry-After', 'not set')}; {response.text[:1500]}")
        if 300 <= response.status_code < 400:
            raise RuntimeError("Unexpected redirect; inspect the endpoint instead of forwarding credentials")
        return response

    @staticmethod
    def data(response):
        return response.json() if response.content else {}

    def complete_operation(self, response):
        if response.status_code != 202:
            return self.data(response)
        operation_id = response.headers.get("x-ms-operation-id")
        url = response.headers.get("Location")
        if operation_id:
            url = BASE + "/operations/" + operation_id
        if not url:
            raise RuntimeError("202 response missing operation tracking headers")
        deadline = time.monotonic() + 900
        delay = int(response.headers.get("Retry-After", "5"))
        while time.monotonic() < deadline:
            time.sleep(max(1, delay))
            current = self.request("GET", url)
            data = self.data(current)
            status = data.get("status", "")
            print("Definition operation:", status)
            if status == "Succeeded":
                return self.data(self.request("GET", url.rstrip("/") + "/result"))
            if status in {"Failed", "Cancelled"}:
                raise RuntimeError(json.dumps(data))
            delay = int(current.headers.get("Retry-After", "5"))
        raise TimeoutError("Operation still pending after 15 minutes; inspect Fabric before retrying")


def definition_payload(content):
    encoded = base64.b64encode(json.dumps(content).encode("utf-8")).decode("ascii")
    return {"definition": {"parts": [{"path": "pipeline-content.json",
            "payload": encoded, "payloadType": "InlineBase64"}]}}


def main():
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("command", choices=["list", "create", "build-etl", "deploy", "export", "run", "status", "watch"])
    parser.add_argument("--file", default="pipeline_smoke.json")
    args = parser.parse_args()
    config = load_json(ROOT / "config.json")
    workspace_id = guid(config["workspace_id"])
    state = load_json(STATE_FILE) if STATE_FILE.exists() else {}
    if state and state.get("workspace_id") != workspace_id:
        raise ValueError("Saved state belongs to another workspace; use a separate lab folder")
    if args.command == "build-etl":
        notebook_id = guid(config["notebook_id"])
        content = load_json(ROOT / "pipeline_smoke.json")
        content["properties"]["description"] = "Sales medallion notebook orchestrated from VS Code"
        content["properties"]["activities"].append({
            "name": "RunSalesETL", "type": "TridentNotebook",
            "dependsOn": [{"activity": "WaitForConnectivity", "dependencyConditions": ["Succeeded"]}],
            "policy": {"timeout": "0.01:00:00", "retry": 0, "retryIntervalInSeconds": 30,
                       "secureInput": False, "secureOutput": False},
            "typeProperties": {"notebookId": notebook_id, "workspaceId": workspace_id}})
        save_json(ROOT / "pipeline_etl.json", content)
        print("Created pipeline_etl.json locally. Review before deploying.")
        return
    client = FabricClient()
    pipeline_id = state.get("pipeline_id")
    prefix = f"workspaces/{workspace_id}"
    if args.command == "list":
        url = prefix + "/items"
        while url:
            data = client.data(client.request("GET", url))
            for item in data.get("value", []):
                print(item.get("type"), item.get("displayName"), item.get("id"))
            url = data.get("continuationUri")
        return
    if args.command == "create":
        if pipeline_id:
            raise ValueError("A pipeline ID is already saved. Use deploy instead of creating again.")
        body = definition_payload(load_json(ROOT / args.file))
        body.update(displayName=config["pipeline_name"], description="Isolated VS Code sales lab")
        response = client.request("POST", prefix + "/dataPipelines", body)
        item = client.complete_operation(response)
        if not item.get("id"):
            raise RuntimeError("No item ID returned. Inspect workspace items before repeating create.")
        state = {"workspace_id": workspace_id, "pipeline_id": guid(item["id"])}
        save_json(STATE_FILE, state)
        print("Created pipeline:", state["pipeline_id"])
        return
    if not pipeline_id:
        raise ValueError("No saved pipeline ID. Complete create first.")
    pipeline_id = guid(pipeline_id)
    item_path = prefix + "/dataPipelines/" + pipeline_id
    if args.command == "deploy":
        response = client.request("POST", item_path + "/updateDefinition",
                                  definition_payload(load_json(ROOT / args.file)))
        client.complete_operation(response)
        print("Pipeline definition deployed; not executed.")
    elif args.command == "export":
        data = client.complete_operation(client.request("POST", item_path + "/getDefinition", {}))
        save_json(ROOT / "exported-definition.json", data)
        parts = data.get("definition", data).get("parts", [])
        for part in parts:
            if part.get("path") == "pipeline-content.json":
                content = json.loads(base64.b64decode(part["payload"]).decode("utf-8-sig"))
                save_json(ROOT / "pipeline_exported.json", content)
                print("Saved pipeline_exported.json and exported-definition.json")
                break
        else:
            raise RuntimeError("Definition returned no pipeline-content.json part")
    elif args.command == "run":
        # A job Location is a job-instance URL, not an item-definition operation URL.
        response = client.request("POST", prefix + f"/items/{pipeline_id}/jobs/Pipeline/instances", {})
        location = response.headers.get("Location")
        data = client.data(response)
        if not location and data.get("id"):
            location = BASE + "/" + prefix + f"/items/{pipeline_id}/jobs/instances/{data['id']}"
        if not location:
            raise RuntimeError("No run URL returned. Check Fabric run history before submitting again.")
        state["run_url"] = location
        save_json(STATE_FILE, state)
        print("Run submitted. Use status or watch; accepted does not mean succeeded.")
    else:
        url = state.get("run_url")
        if not url:
            raise ValueError("No saved run. Use run first.")
        deadline = time.monotonic() + 1800
        while True:
            response = client.request("GET", url)
            data = client.data(response)
            status = data.get("status", "Unknown")
            print(json.dumps({k: data.get(k) for k in ["id", "status", "startTimeUtc", "endTimeUtc", "failureReason"]}, indent=2))
            if args.command == "status":
                return
            if status in {"Completed", "Succeeded"}:
                return
            if status in {"Failed", "Cancelled", "Deduped"}:
                raise RuntimeError("Job did not complete successfully: " + status)
            if time.monotonic() >= deadline:
                raise TimeoutError("Monitoring stopped after 30 minutes; Fabric job may still be running")
            time.sleep(max(1, int(response.headers.get("Retry-After", "10"))))


if __name__ == "__main__":
    main()

What is the difference between Save, Deploy and Run?

Save persists a local file. Deploy sends a definition to Fabric. Run submits execution of the remote pipeline. Notebook deployment is a separate item operation from pipeline definition deployment.

Can the laptop CSV be read directly by Fabric Spark?

No. Upload it to OneLake or use another configured reachable source. The provided notebook reads the uploaded Files/inbound/sales.csv path.

Why start with a Wait activity?

It isolates identity, permissions and orchestration from notebook/data problems. It is a diagnostic training step.

Why retain the exported definition?

It preserves the service’s effective configuration, including connection bindings that may not exist in the minimal locally generated activity.
