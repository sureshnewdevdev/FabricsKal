3. Trainer pre-work (before class)

  1. Confirm each participant has an organization-approved Copilot license/entitlement and can sign in.
  2. Confirm Git host (GitHub or Azure DevOps), repository URL, and permission to create branches and pull requests.
  3. Provide a sanitized sample repository containing sample SQL, Markdown and non-sensitive configuration.
  4. Confirm company software installation and extension policies; allow installation or arrange IT-managed deployment.
  5. Check corporate proxy/firewall allows VS Code extension marketplace, Git host, and Copilot endpoints.
  6. Pair participants for instruction and prompt peer reviews.
  7. Arrange Fabric workspace permissions before Day 2, not as a blocker for Day 1.

4. Install Visual Studio Code

Official download: code.visualstudio.com/Download

  1. Open the link and choose the Windows Stable installer appropriate for your device (usually x64 User Installer).
  2. Run the installer; accept company-approved options and license terms.
  3. Consider enabling Add to PATH and Open with Code context menu options.
  4. Complete installation and launch VS Code.
  5. Open Terminal → New Terminal and verify:
code --version

If code is not recognized, restart the terminal or VS Code; verify the PATH option. You can still use VS Code from the Start menu.

5. Install Git for Windows

Official download: git-scm.com/downloads/win

  1. Download the official Git for Windows installer.
  2. Run it with organization-approved defaults. Keep the Git Credential Manager option enabled if available.
  3. Restart VS Code so the terminal sees the Git executable.
  4. Verify installation and configure your identity using your actual work details:
git --version
git config --global user.name "Your Full Name"
git config --global user.email "your.name@company.com"
git config --global --list
Security: Do not paste passwords or personal access tokens into scripts, prompts, or checked-in files. Use approved browser/device login and credential management.

6. Set up GitHub Copilot

  1. In VS Code, select Extensions (Ctrl+Shift+X).
  2. Search for GitHub Copilot, confirm publisher GitHub, and install the approved extension.
  3. If the installed VS Code version requires a separate GitHub Copilot Chat extension, install it too; some versions bundle or integrate chat.
  4. Click the Copilot icon or Chat view and select Sign in.
  5. Authenticate with the account assigned the organization's Copilot entitlement.
  6. Open a non-sensitive test file and ask Copilot Chat: Explain the purpose of this SQL query in three bullets.
  7. Check that chat responds and that your organization permits the selected chat mode/model.

Reference: VS Code Copilot setup documentation

Do not use customer policyholder information or confidential insurance data for the first demo. Use synthetic records only.

8. Connect the Git repository and create a pull request

  1. Get the approved repository URL from the trainer. In VS Code, press Ctrl+Shift+P → Git: Clone.
  2. Paste the URL, choose a local folder, and open the cloned project.
  3. Open a terminal and create a feature branch:
git checkout -b feature/day1-copilot-setup
git status
  1. Make a small, reviewed change such as adding a README training note.
  2. Stage and commit:
git add README.md
git commit -m "docs: add Day 1 Copilot setup notes"
git push -u origin feature/day1-copilot-setup
  1. Open GitHub or Azure DevOps in a browser, select Create pull request, choose the base branch, add summary/test notes, and request a peer review.
  2. Ask Copilot to draft a commit message and PR description, then manually verify every claim before submission.
Example prompt: “Based only on the changes shown in this diff, draft a concise pull request description with Summary, Testing and Risks. Do not claim tests were executed unless evidence is provided.”

9. Create workspace-level VS Code settings

In the project root, create .vscode/settings.json. The schedule specifically asks participants to disable Copilot for JSON and secret-related files. The following illustrates the editor language-level exclusion; do not assume it protects every secret file or chat attachment.

{
  "github.copilot.enable": {
    "*": true,
    "json": false,
    "jsonc": false,
    "plaintext": false
  },
  "files.exclude": {
    "**/.env": true,
    "**/.env.*": true
  }
}
Important limitation: files.exclude hides files in the Explorer; it is not an access-control or AI-data-protection boundary. Secret file extensions vary. Use organization-managed Copilot content exclusions where supported, repository access controls, .gitignore, secret scanning and a policy against pasting secrets into chat. Confirm effective exclusions with your administrator.

Save and commit the settings file. Validate settings against your installed extension version and company policy.

10. Custom instructions and reusable prompts

A. Repository instructions

Create .github/copilot-instructions.md at the repository root (the file convention used by GitHub Copilot for repository-wide instructions).

# Copilot instructions — Insurance BI ETL
- Use clear, descriptive SQL object names.
- Prefer incremental loads only when the approved load specification requires them.
- Never invent source columns or business rules.
- Do not include credentials, tokens or customer PII.
- Explain assumptions and provide edge-case tests.
- Do not change FULL-load behavior without explicit approval.
- Treat generated SQL as a draft requiring human review.

Ask a teammate to review these instructions and test whether Copilot follows them.

B. Reusable prompt

Create .github/prompts/review-etl.prompt.md:

---
description: Review an ETL SQL change for correctness and risk
---
Review the selected SQL change using these checks:
1. Load type: FULL vs INCREMENTAL behavior
2. Nulls, duplicates and missing keys
3. Transaction handling and rollback
4. Data exposure and hardcoded secrets
5. Performance risks and indexes
Return: Findings, Severity, Evidence, Suggested Tests.
Do not assume a test has passed unless its result is provided.

In a supported Copilot Chat version, invoke the reusable prompt from the chat prompt picker or by typing /review-etl. A prompt file is a reusable workflow; it is not necessarily the same as an agent skill. The exact UI varies by VS Code/Copilot version.

11. End-to-end verification (trainer demo)

  1. VS Code opens the sample repository.
  2. git --version succeeds.
  3. Copilot Chat answers a synthetic SQL question.
  4. .vscode/settings.json exists and is committed.
  5. .github/copilot-instructions.md exists and has peer feedback.
  6. A teammate can invoke or reuse the prompt without editing its text.
  7. A feature branch is pushed and a PR is opened.

Simple training SQL for testing Copilot

SELECT PolicyId, SUM(PremiumAmount) AS TotalPremium
FROM dbo.PolicyTransactions
WHERE TransactionDate >= '2026-01-01'
GROUP BY PolicyId;

Ask Copilot to identify potential data-quality edge cases and suggest validation queries. Treat its suggestions as hypotheses, not verified facts.

12. Common troubleshooting

Copilot says “No access” or asks to subscribe

Confirm that the signed-in account is the organization-approved account with Copilot entitlement. Check enterprise policies and contact the administrator; a local reinstall usually will not fix a missing entitlement.

Extensions cannot install

Check company Marketplace restrictions, proxy settings, firewall and allowed publishers. Ask IT for approved deployment rather than downloading unknown extension packages.

Git authentication or push fails

Confirm repository URL, account, branch permission, credential manager login and network access. Protected branches often prohibit direct pushes; push your feature branch and open a PR.

Copilot ignores instructions

Confirm exact file path, supported VS Code/Copilot version, instruction settings and whether repository context was loaded. Instructions guide behavior but do not guarantee compliance; review every output.

JSON settings are not taking effect

Check JSON syntax, language IDs, workspace trust and whether settings are overridden by policy. Confirm exclusions separately with enterprise administrators.
