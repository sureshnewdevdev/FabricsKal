2. Installation on Windows

  1. Install Visual Studio Code; open the application.
  2. Install Git for Windows and Python. Reopen VS Code and run git --version and python --version in its terminal.
  3. Open VS Code → Extensions (Ctrl+Shift+X) → search GitHub Copilot → Install → sign in with your authorized GitHub account.
  4. Search and install Python, Pylance and Jupyter. Add SQL Server (mssql) and GitHub Pull Requests only if needed.
  5. Open Microsoft Fabric; select or create a workspace with available Fabric capacity/trial, then create a Lakehouse named InsuranceDemoLH.
  6. In Fabric, create a notebook and attach the Lakehouse as its default Lakehouse.

Optional: install extensions using the VS Code terminal

3. ETL demo architecture

CSV policy records → VS Code + Copilot → Fabric notebook / Spark → Lakehouse Delta table → SQL / Power BI

Example rule: exclude records with missing policy IDs, normalize policy status and calculate premium after a 10% tax. The sample uses fictional data only.

4. Hands-on: build ETL with Copilot

Step A — Ask Copilot to create a PySpark transform

In VS Code Copilot Chat, paste:

Act as a Microsoft Fabric PySpark ETL developer.
Create a Fabric notebook script that reads fictional policy data,
removes records with blank policy_id, trims status, casts premium
as decimal, calculates premium_with_tax at 10%, and writes
Delta table insurance_policy_silver using overwrite for a demo.
Include input checks, assertions, and explanations.
Do not use secrets, real customer data, or external services.

Step B — Save this starter code in VS Code

Create policy_etl.py. Review the generated code against this reference:

from pyspark.sql import functions as F
from pyspark.sql.types import StructType, StructField, StringType

rows = [
    ("P001", "active", "1000.00"),
    ("P002", " expired ", "2500.00"),
    ("", "active", "700.00"),
]
schema = StructType([
    StructField("policy_id", StringType(), True),
    StructField("status", StringType(), True),
    StructField("premium", StringType(), True),
])
source = spark.createDataFrame(rows, schema)

silver = (
    source
    .withColumn("policy_id", F.trim("policy_id"))
    .filter(F.col("policy_id").isNotNull() & (F.col("policy_id") != ""))
    .withColumn("status", F.upper(F.trim("status")))
    .withColumn("premium", F.col("premium").cast("decimal(12,2)"))
    .filter(F.col("premium").isNotNull())
    .withColumn("premium_with_tax", (F.col("premium") * F.lit("1.10")).cast("decimal(12,2)"))
)

assert silver.count() == 2
assert silver.filter(F.col("premium_with_tax").isNull()).count() == 0
silver.write.format("delta").mode("overwrite").saveAsTable("insurance_policy_silver")
display(silver)
Execution location: this code expects the spark session and display function supplied by a Fabric notebook. It is not directly runnable with plain local Python in VS Code. Copy it into a Fabric notebook cell and execute there. Overwrite is for this demo only; production load patterns need explicit requirements and approvals.

Step C — Run in Fabric

  1. In the Fabric workspace, open the notebook attached to InsuranceDemoLH.
  2. Paste the reviewed code into a PySpark cell.
  3. Run the cell and wait for the Spark session to start.
  4. Expand Lakehouse → Tables and verify insurance_policy_silver.
  5. Open the table preview and verify the two valid records.

5. Validate the output

Expected rows: P001, ACTIVE, 1000.00, 1100.00 and P002, EXPIRED, 2500.00, 2750.00. The empty policy ID is excluded.

SELECT policy_id, status, premium, premium_with_tax
FROM insurance_policy_silver
ORDER BY policy_id;

Run SQL using a compatible Fabric SQL query surface, such as the Lakehouse SQL analytics endpoint. Notebook PySpark SQL also supports spark.sql(...).

7. Security and governance

  • Use fictional data for training; never paste credentials, personal data or insurance claims into prompts without approval.
  • Validate AI-generated transformation rules against written business requirements.
  • Keep secrets out of source control; use approved identity and secret-management methods.
  • Require human review before changing production tables or deployment pipelines.
