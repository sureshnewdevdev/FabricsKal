LESSON 01Understand the task

Configure Copilot for one project, keep suggestions available in JavaScript, disable inline suggestions in JSON and selected secret files, then save the configuration in Git.

Know the boundary. These settings control Copilot inline suggestions. They do not prevent Copilot Chat or agents from reading files. A Git ignore rule also does not create an AI access restriction.

LESSON 02What “json: false” means

"json": false tells Copilot: do not show inline code suggestions in files whose VS Code language mode is JSON. JSON is commonly used for application configuration and structured data.

setting fragment
"json": false

This line belongs inside the github.copilot.enable object. It is not a complete settings file on its own.

For example, while editing config.json, you might begin a property:

unfinished JSON for demonstration
{
  "applicationName": "SalesApp",
  "database":
}

The unfinished example is deliberately invalid JSON until you supply a value. With inline suggestions enabled, Copilot may propose a value after the colon. With "json": false, it will not offer that Copilot inline completion.

LESSON 06Configure workspace settings

JSON · .vscode/settings.json
{
  "github.copilot.enable": {
    "*": true,
    "json": false,
    "jsonc": false,
    "plaintext": false,
    "markdown": false,
    "scminput": false
  },
  "files.associations": {
    ".env": "plaintext",
    ".env.*": "plaintext",
    "*.secret": "plaintext",
    "**/secrets/**": "plaintext"
  }
}

If this file already exists, merge the entries into its existing outer object. Keep one outer pair of braces and avoid duplicate setting keys.

EntryEffect
"*": trueAllows inline suggestions for other language modes.
"json": falseDisables inline suggestions in JSON.
"jsonc": falseDisables inline suggestions in JSON with Comments, including VS Code settings.
"plaintext": falseDisables inline suggestions in all Plain Text files.
markdown / scminput: falseKeeps Markdown and source-control input suggestions disabled in this sample.
files.associationsMaps selected file patterns to Plain Text.

How the secret-file workaround works

.env, .env.*, *.secret and files inside a secrets folder are opened as Plain Text. Since Copilot is disabled for Plain Text, those files do not get Copilot inline suggestions.

Tradeoff: mapping to Plain Text removes their original language-specific highlighting and editor features. It also disables suggestions in ordinary Plain Text files. Only the listed filename patterns are covered; files named credentials.yaml, for example, are not covered unless they are inside a mapped secrets folder.

Avoid this mistake: ".env": false or "secrets.json": false inside github.copilot.enable does not target those filenames. This object expects language identifiers.

LESSON 08Keep local secrets out of Git

gitignore · .gitignore
# Local environment files
.env
.env.*

# Shareable placeholder template
!.env.example

# Local secret files
secrets/
*.secret

! makes an exception: .env.example may be committed although the broader .env.* pattern is ignored.

Separate responsibilities: settings.json controls inline suggestions; .gitignore controls which untracked files Git ignores. Neither is a general restriction on Copilot Chat or agent access.

These rules apply to untracked files. If a file was already tracked, adding an ignore rule does not untrack it or erase earlier commits. This lab uses a new repository.

  2. Press Ctrl + Shift + P.
  3. Run Developer: Reload Window.

A. Establish the positive test

Temporarily replace app.js with:

JavaScript · temporary test
// Calculate the total amount from price and quantity
function calculateTotal(price, quantity) {

Press Enter after the opening brace and pause. Copilot may show dimmed suggested text such as return price * quantity;. You can accept a suggestion with Tab. A suggestion is not guaranteed on every edit, so first confirm Copilot is signed in and working.

B. Test JSON

In config.json, add a comma after the last property and begin a new property. Copilot ghost text should not appear. Regular editor completion lists may still appear. Restore valid JSON afterwards.

C. Test secrets

In .env, type NEW_SETTING=. Confirm the language mode is Plain Text and Copilot inline suggestions are disabled. Repeat in secrets/database.secret.

D. Restore the finished files

Restore the complete app.js and valid config.json from the previous section before committing. Absence of suggestions alone is not proof that settings worked; check the effective settings and language modes as well.

Method 3 · Windows File Explorer

Right-click a file in VS Code Explorer → Reveal in File Explorer. To inspect the full path, use Copy Path. In Windows File Explorer enable View → Show → File name extensions to confirm the filename does not end in an extra .txt.

Method 4 · PowerShell terminal

PowerShell
Get-Location

Get-ChildItem -Force .vscode

Reopen the project later

Use File → Open Recent and choose copilot-settings-demo, or use File → Open Folder again. Your saved workspace settings will be loaded with the folder.

LESSON 11Commit the configuration

Open Terminal → New Terminal. Run Get-Location and confirm you are in copilot-settings-demo. Run the following commands in order.

PowerShell · initialize and inspect
git init
git status --short

Expect the five intended files to be untracked. .env and secrets/database.secret should not be listed because they are ignored.

PowerShell · verify ignore rules
git check-ignore .env secrets/database.secret

Expected output lists both ignored paths.

PowerShell · stage and review
git add .vscode/settings.json .gitignore .env.example app.js config.json
git diff --cached --name-only
git diff --cached

Review the staged changes. Confirm that only settings, sample code, safe JSON and the placeholder template are included.

PowerShell · commit and verify
git commit -m "Configure workspace Copilot suggestions for JSON and secret files"
git log -1 --oneline
git status --short

Expected: one commit entry and no output from the final status command if there are no other changes. The commit is local; it does not upload the project to GitHub.

If Git asks for an identity

Use your own details. These commands set the identity only for this repository:

PowerShell
git config user.name "Your Name"
git config user.email "your-email@example.com"

Run the commit command again. To see the paths saved in the commit:

PowerShell
git ls-tree -r --name-only HEAD

LESSON 12Troubleshooting and completion

ProblemAction
JSON still gets ghost textCheck the bottom-right language mode, save settings, reload, and inspect effective json/jsonc settings.
.env opens as another languageCheck files.associations and reload the window. Do not manually switch it away from Plain Text during this test.
JavaScript shows no suggestionsCheck Copilot sign-in, available access, and whether suggestions are enabled.
settings.json shows errorsCheck commas, matching braces and duplicate keys.
Settings do not applyConfirm the correct project folder is open. Check language-specific overrides or enforced policies if present.
Files are missing from ExplorerCheck Explorer filters or files.exclude; open the exact path through File → Open File.
Git says “not a git repository”Check your terminal location and run git init in the sample project.
A secret file is stagedStop before committing. Unstage it with git restore --staged PATH, then investigate its tracked/ignore state.

Review question: Does "json": false prevent Copilot Chat from reading JSON?

Show explanation

No. It disables Copilot inline suggestions for the JSON language mode. File access by Chat and agents is a separate concern.

Official reference notes

Administrator-managed content exclusion is available for organizations with Copilot Business or Enterprise. GitHub documents that Copilot CLI and IDE Agent mode do not support those exclusions. Do not describe this workspace configuration as a security boundary.
