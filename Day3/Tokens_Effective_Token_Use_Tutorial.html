LESSON 02Tokens, context and output

A token is a unit of text handled by a language model. It may represent part of a word, a whole word, punctuation or other text. A token is not the same as a word, character or line of code.

TermMeaningExample
Input tokensTokenized material supplied to the modelYour question, code and instructions
Output tokensTokens generated by the modelExplanation and suggested fix
Context windowThe model’s available context capacityInstructions, conversation and relevant sources
Context overheadMaterial beyond the file you supplySystem guidance, tool definitions and history

Short variable names, punctuation, long strings and language scripts can tokenize differently. A 500-line file has no universal token count. The tokenizer depends on the model.

Do not ask Copilot to guess how many tokens it used and call the answer a measurement. Prefer an exposed usage metric or a matching tokenizer when available; label all estimates clearly.

Effective token use: supply the smallest context that still contains the information needed to answer correctly.

LESSON 03Why scoping can help

For a local arithmetic bug, unrelated catalog-formatting functions do not explain the faulty calculation. Including them increases the source material you supply and may distract from the relevant function.

However, removing too much can hide imports, constants, helper functions or business rules. The goal is sufficient context, not the fewest possible lines.

Keep for this questionRemove from the focused copy
calculate_invoiceUnrelated display functions
Decimal importCatalog labeling utilities
HUNDRED and PAISE constantsUnrelated formatting comments
validate_inputs helperOther workflow sections
Percentage contract and example callOther feature examples

A file attachment is a convenient way to identify the source. Its contents or retrieved snippets still contribute to model context. Attaching instead of pasting does not guarantee lower token usage.

LESSON 05Inspect the code and question

Python · invoice_scoped.py
"""Focused invoice example. discount_percent is a percent such as 10."""
from decimal import Decimal

HUNDRED = Decimal("100")
PAISE = Decimal("0.01")


def validate_inputs(subtotal: Decimal, discount_percent: Decimal) -> None:
    if not subtotal.is_finite() or subtotal < 0:
        raise ValueError("subtotal must be finite and non-negative")
    if not discount_percent.is_finite() or not 0 <= discount_percent <= HUNDRED:
        raise ValueError("discount_percent must be between 0 and 100")


def calculate_invoice(subtotal: Decimal, discount_percent: Decimal) -> Decimal:
    """Return payable INR after a percentage discount, rounded to paise."""
    validate_inputs(subtotal, discount_percent)
    # Intentional bug: the percentage is not converted into a fraction.
    discount_amount = subtotal * discount_percent
    payable_amount = subtotal - discount_amount
    return payable_amount.quantize(PAISE)


if __name__ == "__main__":
    print(calculate_invoice(Decimal("1000"), Decimal("10")))

The example accepts a discount percentage of 10 for 10%. It currently multiplies ₹1,000 by 10 rather than converting 10% to 0.10.

The exact question for all three trials

The bug is missing division by 100:

smallest fix

LESSON 06Prepare a fair comparison

  1. Use the same selected model for A, B and C. Avoid automatic model changes where you can select a fixed model.
  2. Use the same non-editing Chat/Ask mode where available. Agents may search/read more files and change the context under test.
  3. Start a new chat before each trial. Do not run B and C as follow-ups to A.
  4. Close unrelated source tabs. Inspect suggested attachments and remove unneeded ones from the chat input; do not delete project files.
  5. Keep project instructions and settings consistent across the three trials.
  6. Use the same question and 150-word limit each time.
  7. Record references, automatic attachments, extra searches and file reads if any occur.
A fresh chat reduces history differences; it does not remove built-in instructions or guarantee that workspace retrieval is absent. If Copilot reads extra files despite the prompt, record the run as having additional context.

Measure time consistently: start at Send and stop when the answer finishes. Network load and caching can affect time. A single fast answer does not prove a token-saving effect.

LESSON 10Document the actual differences

Where your installed VS Code surface exposes a context-window control, hover it to inspect the available token usage/category breakdown. Record the exact label shown.

A context occupancy value is not necessarily per-request input tokens, total processed tokens or billable usage. “Before” and “after” may include the response and tool messages. If a request-level metric is available, record it separately.

If no token count is shown, write not shown. Source character count and line count can still support a comparison of supplied text volume.

TimeSeconds from Send to completionAffected by caching/network/server load
QualityScore out of four with evidenceMust evaluate the answer, not only size
Extra contextReferences, tool reads or searchesCan confound controlled trials

Score each answer out of four

  1. Identifies percentage-to-fraction conversion as the bug.
  2. Shows the one-line division by HUNDRED.
  3. Gives the correct result, 900.00.
  4. Avoids unrelated changes or invented dependencies.

Effective token-use habits

  • Name the target function and the specific question.
  • Include necessary dependencies and expected behavior.
  • Request an answer length suitable for the task.
  • Attach focused sources instead of unrelated folders or long logs.
  • Use a fresh chat for a separate experiment or unrelated task.
  • Add further context when the model identifies a genuine missing dependency.

Use model-specific context limits and current exposed usage controls; do not teach one universal limit or a fixed rupee cost per request.

Questions learners may ask

Are 500 lines equal to 500 tokens?

No. Token counts depend on the actual text and tokenizer. Lines are a file-size measure.

Does #file save tokens automatically?

No. It names an explicit source. Its included content consumes context; how much is included depends on the IDE’s context assembly.

Must I remove the other files?

No. Keep the files. Control which source you paste or attach, and record any extra automatic context.

Does a lower context percentage prove lower cost?

No. Context occupancy and processed/billable usage are different measurements. Record the metric’s scope.

When should I include a large file?

When the question depends on multiple parts of it, such as cross-function behavior or a module-wide refactor. Scope based on the task.
