09 — Generate Silver notebook with Copilot

Paste into GitHub Copilot Chat (Local)
 prompt
Read 01_bronze.py and the CSV. Generate Fabric PySpark transformations for integer order_id, date order_date, decimal price and quantity, trimmed names, reject rows with invalid mandatory fields, deduplicate by order_id using deterministic ordering, derive sales_amount, save silver_sales and silver_rejected_sales as Delta. Add assertions for row count and sum 182250.00.

Review type casts, rejected-row logic and deduplication. A full reference implementation is included:

 python
# 02_silver.py — clean, validate, quarantine invalid rows and deduplicate
from pyspark.sql import functions as F
from pyspark.sql.window import Window
raw = spark.table("bronze_sales")
df = (raw.select(
    F.col("order_id").cast("int").alias("order_id"),
    F.to_date("order_date", "yyyy-MM-dd").alias("order_date"),
    F.trim("customer_id").alias("customer_id"),
    F.trim("customer_name").alias("customer_name"),
    F.trim("product_id").alias("product_id"),
    F.trim("product_name").alias("product_name"),
    F.trim("category").alias("category"),
    F.col("quantity").cast("int").alias("quantity"),
    F.col("unit_price").cast("decimal(12,2)").alias("unit_price"),
    F.trim("region").alias("region"),
    "ingested_at"))
valid = (F.col("order_id").isNotNull() & F.col("order_date").isNotNull() &
         F.col("customer_id").isNotNull() & (F.length("customer_id") > 0) &
         F.col("product_id").isNotNull() & (F.length("product_id") > 0) &
         F.col("quantity").isNotNull() & (F.col("quantity") > 0) &
         F.col("unit_price").isNotNull() & (F.col("unit_price") >= 0))
rejected = df.filter(~valid).withColumn("reject_reason", F.lit("Invalid required field/date/quantity/price"))
rejected.write.format("delta").mode("overwrite").option("overwriteSchema", "true").saveAsTable("silver_rejected_sales")
w = Window.partitionBy("order_id").orderBy(F.col("ingested_at").desc())
clean = (df.filter(valid).withColumn("rn", F.row_number().over(w))
         .filter("rn = 1").drop("rn")
         .withColumn("sales_amount", (F.col("quantity") * F.col("unit_price")).cast("decimal(14,2)")))
clean.write.format("delta").mode("overwrite").option("overwriteSchema", "true").saveAsTable("silver_sales")
print("Silver valid rows:", clean.count(), "Rejected rows:", rejected.count())
display(spark.table("silver_sales"))
  1. Publish 02_silver to Fabric.
  2. Execute only after 01_bronze succeeded.
  3. Validate silver_sales contains 10 rows and silver_rejected_sales contains 0 rows.
  4. Verify sales_amount = quantity × unit_price and the sum is ₹182,250.
If Copilot proposes dropDuplicates(["order_id"]) without deterministic ordering, ask it to explain which record wins; use a consistent ordering rule for duplicates in realistic data.

10 — Generate Gold star schema with Copilot

Paste into GitHub Copilot Chat (Local)
 prompt
Read 02_silver.py. Generate PySpark to create dim_customer, dim_product, dim_date and fact_sales from silver_sales; make stable customer_key and product_key; date_key yyyyMMdd; preserve order grain and test dimension key uniqueness, foreign key matches, fact count 10, sum 182250.00. Discuss why customer region might be order-specific instead of a customer attribute.

Gold fact grain: one row per order_id. Dimensions: customer, product and calendar date. Join keys are stored in the fact table.

 python
# 03_gold.py — star schema; run after 02_silver.py
from pyspark.sql import functions as F
s = spark.table("silver_sales")
customer = (s.select("customer_id", "customer_name", "region")
    .dropDuplicates(["customer_id"])
    .withColumn("customer_key", F.xxhash64("customer_id"))
    .select("customer_key", "customer_id", "customer_name", "region"))
product = (s.select("product_id", "product_name", "category")
    .dropDuplicates(["product_id"])
    .withColumn("product_key", F.xxhash64("product_id"))
    .select("product_key", "product_id", "product_name", "category"))
bounds = s.agg(F.min("order_date").alias("lo"), F.max("order_date").alias("hi")).first()
assert bounds["lo"] is not None, "Silver contains no valid orders"
dates = spark.range(1).select(F.explode(F.sequence(F.lit(bounds["lo"]), F.lit(bounds["hi"]))).alias("full_date"))
date = (dates.withColumn("date_key", F.date_format("full_date", "yyyyMMdd").cast("int"))
    .withColumn("year", F.year("full_date"))
    .withColumn("month_number", F.month("full_date"))
    .withColumn("month_name", F.date_format("full_date", "MMMM"))
    .withColumn("day_name", F.date_format("full_date", "EEEE")))
fact = (s.withColumn("customer_key", F.xxhash64("customer_id"))
    .withColumn("product_key", F.xxhash64("product_id"))
    .withColumn("date_key", F.date_format("order_date", "yyyyMMdd").cast("int"))
    .select("order_id", "date_key", "customer_key", "product_key", "quantity", "unit_price", "sales_amount"))
for name, frame in [("dim_customer", customer), ("dim_product", product), ("dim_date", date), ("fact_sales", fact)]:
    frame.write.format("delta").mode("overwrite").option("overwriteSchema", "true").saveAsTable(name)
print("Gold rows:", fact.count(), "Total INR:", fact.agg(F.sum("sales_amount")).first()[0])
display(spark.table("fact_sales"))
Data-model nuance: in this sample each customer has one region. In a real sales model, if one customer can order from different regions, put the transaction region in the fact or model it with a separate region dimension rather than treating it as a permanent customer property.

Publish and run 03_gold after Silver. Check 10 fact rows, 8 customers, 4 products, 5 calendar dates. Review generated keys and confirm no orphan foreign keys.
