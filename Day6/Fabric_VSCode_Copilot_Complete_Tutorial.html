01 · Objective, roles and architecture

Build a repeatable end-to-end Microsoft Fabric sales pipeline with VS Code + GitHub Copilot for authoring and review, Fabric Data Factory for ingestion and orchestration, Fabric Spark notebooks for transformations, Lakehouse Delta tables for storage, and Power BI for analytics.

VS Code + GitHub Copilot (author code & prompts) → Fabric workspace (run)
Source CSV → Lakehouse Files/incoming → Copy Data pipeline → Files/bronze → Bronze notebook/table → Silver notebook/tables → Gold notebook/star schema → Power BI semantic model/report

Important: GitHub Copilot in VS Code is different from Fabric Copilot. Fabric Copilot availability on F2 may depend on tenant settings, capacity rules, and licensing; this lab does not depend on Fabric Copilot. Spark notebooks and Data Factory activities run in Fabric, not inside local VS Code.

02 · Prerequisites and exact responsibilities

  1. Have access to a Fabric-enabled workspace on the intended F2 capacity. Verify the workspace can create Lakehouses, Data Pipelines and Notebooks, and that you have write permission.
  2. Install VS Code, Python extension, GitHub Copilot and GitHub Copilot Chat (as offered in VS Code), sign in to GitHub and confirm your Copilot entitlement. Python 3.11 is optional for local CSV checks; Spark executes in Fabric.
  3. Open the extracted lab folder in VS Code using File → Open Folder. Locate data/sales_orders.csv, notebooks/*.py and prompts/copilot_prompts.md.
  4. Open https://app.fabric.microsoft.com and select your workspace. Confirm the desired Fabric capacity and available notebook execution before proceeding.
  5. Power BI report creation requires appropriate Fabric/Power BI access and semantic model permissions; UI labels can change.

F2 note: small capacity may have Spark startup delays or capacity pressure. Do not assume F2 alone enables Fabric Copilot.

04 · Create Fabric Lakehouse and source landing folder

  1. Fabric → workspace → New item → Lakehouse → name lh_sales_medallion → Create.
  2. Open the Lakehouse → Files → create folder incoming. Create another folder bronze (the pipeline can also create its target folder).
  3. Upload sales_orders.csv from your computer into Files/incoming/. Check file size and preview the header. This is a one-time seed of the source; the pipeline, not manual upload, will move it into Bronze.
  4. Confirm the source exists at Files/incoming/sales_orders.csv. Keep the same file name for all subsequent steps.

Production variation: the pipeline Copy activity can read Azure Blob Storage, ADLS Gen2 or another authorized external source instead of the seeded Lakehouse folder. The local VS Code folder is not itself a Fabric pipeline connector.

05 · Build Bronze ingestion with Fabric Data Pipeline

  1. Workspace → New item → Data pipeline → name pl_sales_medallion.
  2. In pipeline editor, add Copy data activity; rename it Copy_Sales_To_Bronze.
  3. Source: select Lakehouse connector / workspace Lakehouse lh_sales_medallion; source root Files; browse incoming/sales_orders.csv. Choose CSV/delimited text; first row as header where the UI exposes this option.
  4. Destination: Lakehouse lh_sales_medallion, root Files, path bronze/sales_orders.csv. Choose a file destination, not a Delta table. Configure overwrite for repeatable training runs where supported; otherwise clear the target file before rerunning.
  5. Save the pipeline, then use Run / Debug and inspect the Copy activity output: status Succeeded, source rows/file and bytes copied as available.
  6. Return to the Lakehouse and verify Files/bronze/sales_orders.csv exists. Only now proceed to Bronze notebook.

UI differences: some Fabric experiences call this Copy data assistant or Copy activity. Follow the same source and destination intent; do not use a Notebook activity to perform the initial copy.

07 · Create and run Bronze notebook

  1. Fabric workspace → New item → Notebook → name nb_01_bronze.
  2. Attach the default Lakehouse lh_sales_medallion. Confirm notebook Lakehouse context points to it.
  3. In VS Code open notebooks/01_bronze.py; review with GitHub Copilot; copy its entire contents into a Fabric notebook Python cell.
  4. Run the cell. Wait for the Spark session. The code reads the copied CSV under Files/bronze, adds ingestion metadata, and writes Delta table bronze_sales.
  5. In Lakehouse → Tables verify bronze_sales; expected row count 10. Save notebook.
# 01_bronze.py — paste into a Fabric PySpark notebook attached to lh_sales_medallion
from pyspark.sql import functions as F
SOURCE = "Files/bronze/sales_orders.csv"
raw = spark.read.option("header", True).option("inferSchema", False).csv(SOURCE)
assert raw.count() > 0, "No rows copied to Bronze Files"
(raw.withColumn("ingested_at", F.current_timestamp())
    .withColumn("source_file", F.input_file_name())
    .write.format("delta").mode("overwrite").option("overwriteSchema", "true")
    .saveAsTable("bronze_sales"))
print("Bronze rows:", spark.table("bronze_sales").count())
display(spark.table("bronze_sales"))

08 · Build Silver transformation and data quality

  1. New Fabric notebook → nb_02_silver; attach the same Lakehouse.
  2. In VS Code review notebooks/02_silver.py with Copilot prompt 2.
  3. Copy the Python into the Fabric notebook and run it after Bronze completes.
  4. Inspect silver_sales (clean records, typed dates/prices, computed sales_amount) and silver_rejected_sales (invalid records).
  5. Expected clean rows 10, rejected rows 0. To test quarantine, add a malformed row to the CSV, rerun ingestion and Bronze/Silver, then restore the original file before the final report.

Rule: reject missing identifiers, invalid dates, quantity ≤ 0 and negative unit prices; deduplicate by order_id. In real systems, capture detailed rejection reasons and preserve audit history.

# 02_silver.py — clean, validate, quarantine invalid rows and deduplicate
from pyspark.sql import functions as F
from pyspark.sql.window import Window
raw = spark.table("bronze_sales")
df = (raw.select(
    F.col("order_id").cast("int").alias("order_id"),
    F.to_date("order_date", "yyyy-MM-dd").alias("order_date"),
    F.trim("customer_id").alias("customer_id"),
    F.trim("customer_name").alias("customer_name"),
    F.trim("product_id").alias("product_id"),
    F.trim("product_name").alias("product_name"),
    F.trim("category").alias("category"),
    F.col("quantity").cast("int").alias("quantity"),
    F.col("unit_price").cast("decimal(12,2)").alias("unit_price"),
    F.trim("region").alias("region"),
    "ingested_at"))
valid = (F.col("order_id").isNotNull() & F.col("order_date").isNotNull() &
         F.col("customer_id").isNotNull() & (F.length("customer_id") > 0) &
         F.col("product_id").isNotNull() & (F.length("product_id") > 0) &
         F.col("quantity").isNotNull() & (F.col("quantity") > 0) &
         F.col("unit_price").isNotNull() & (F.col("unit_price") >= 0))
rejected = df.filter(~valid).withColumn("reject_reason", F.lit("Invalid required field/date/quantity/price"))
rejected.write.format("delta").mode("overwrite").option("overwriteSchema", "true").saveAsTable("silver_rejected_sales")
w = Window.partitionBy("order_id").orderBy(F.col("ingested_at").desc())
clean = (df.filter(valid).withColumn("rn", F.row_number().over(w))
         .filter("rn = 1").drop("rn")
         .withColumn("sales_amount", (F.col("quantity") * F.col("unit_price")).cast("decimal(14,2)")))
clean.write.format("delta").mode("overwrite").option("overwriteSchema", "true").saveAsTable("silver_sales")
print("Silver valid rows:", clean.count(), "Rejected rows:", rejected.count())
display(spark.table("silver_sales"))

09 · Build Gold fact and dimension tables

  1. New Fabric notebook → nb_03_gold; attach the same Lakehouse.
  2. Review notebooks/03_gold.py using Copilot prompt 3; copy into Fabric and execute.
  3. Inspect dim_customer (customer_key/customer_id/name/region), dim_product (product_key/product_id/name/category), dim_date (date_key/full_date/calendar attributes), fact_sales (order_id/foreign keys/quantity/price/amount).
  4. Expected fact rows 10 and total sales ₹182,250. Keys use deterministic hashes for the lab. The sample assumes customer and product attributes do not change during the period.
  5. Confirm all four tables appear under Lakehouse Tables.
# 03_gold.py — star schema; run after 02_silver.py
from pyspark.sql import functions as F
s = spark.table("silver_sales")
customer = (s.select("customer_id", "customer_name", "region")
    .dropDuplicates(["customer_id"])
    .withColumn("customer_key", F.xxhash64("customer_id"))
    .select("customer_key", "customer_id", "customer_name", "region"))
product = (s.select("product_id", "product_name", "category")
    .dropDuplicates(["product_id"])
    .withColumn("product_key", F.xxhash64("product_id"))
    .select("product_key", "product_id", "product_name", "category"))
bounds = s.agg(F.min("order_date").alias("lo"), F.max("order_date").alias("hi")).first()
assert bounds["lo"] is not None, "Silver contains no valid orders"
dates = spark.range(1).select(F.explode(F.sequence(F.lit(bounds["lo"]), F.lit(bounds["hi"]))).alias("full_date"))
date = (dates.withColumn("date_key", F.date_format("full_date", "yyyyMMdd").cast("int"))
    .withColumn("year", F.year("full_date"))
    .withColumn("month_number", F.month("full_date"))
    .withColumn("month_name", F.date_format("full_date", "MMMM"))
    .withColumn("day_name", F.date_format("full_date", "EEEE")))
fact = (s.withColumn("customer_key", F.xxhash64("customer_id"))
    .withColumn("product_key", F.xxhash64("product_id"))
    .withColumn("date_key", F.date_format("order_date", "yyyyMMdd").cast("int"))
    .select("order_id", "date_key", "customer_key", "product_key", "quantity", "unit_price", "sales_amount"))
for name, frame in [("dim_customer", customer), ("dim_product", product), ("dim_date", date), ("fact_sales", fact)]:
    frame.write.format("delta").mode("overwrite").option("overwriteSchema", "true").saveAsTable(name)
print("Gold rows:", fact.count(), "Total INR:", fact.agg(F.sum("sales_amount")).first()[0])
display(spark.table("fact_sales"))

10 · Orchestrate Copy → Bronze → Silver → Gold

  1. Return to pl_sales_medallion. Keep Copy_Sales_To_Bronze as first activity.
  2. Add Notebook activity Run_Bronze; select nb_01_bronze, the workspace, and Lakehouse context where exposed.
  3. Connect Copy success (green dependency) → Run_Bronze.
  4. Add Notebook activity Run_Silver; choose nb_02_silver; connect Run_Bronze success → Run_Silver.
  5. Add Notebook activity Run_Gold; choose nb_03_gold; connect Run_Silver success → Run_Gold.
  6. Save. Run pipeline. Open monitoring/output for each activity and check success, duration and errors. Do not assume a pipeline succeeded merely because its start was accepted.
  7. Re-run to check repeatability: this lab overwrites training tables. In production use incremental MERGE, watermarking, logging and retention instead.

11 · Create Power BI semantic model and report

  1. In Fabric open the Lakehouse or its SQL analytics endpoint. Locate the option to create a new semantic model (do not assume one was automatically created).
  2. Select fact_sales, dim_customer, dim_product and dim_date. Name the model sm_sales_gold. Choose the supported Direct Lake mode when available; otherwise follow the available connection mode.
  3. In model view define one-to-many relationships: dim_customer[customer_key] → fact_sales[customer_key]; dim_product[product_key] → fact_sales[product_key]; dim_date[date_key] → fact_sales[date_key]. Use single-direction dimension-to-fact filtering.
  4. Create measures using the DAX below. Set sales measure format to INR currency.
  5. Create a report: cards for Total Sales, Orders, Units Sold; line chart full_date vs Total Sales; bar chart category vs Total Sales; bar chart region vs Total Sales (region is on dim_customer); slicers for date and category.
  6. Save report Sales Performance Dashboard. Validate total ₹182,250 and 10 orders against Gold Delta table totals.
Total Sales = SUM(fact_sales[sales_amount])
Total Orders = DISTINCTCOUNT(fact_sales[order_id])
Units Sold = SUM(fact_sales[quantity])
Average Order Value = DIVIDE([Total Sales], [Total Orders])

If a relationship fails, check matching key data types and unique keys in dimension tables. If a newly created table is missing from the semantic model, refresh the model metadata.

13 · Production enhancements and lab completion checklist

  1. Replace manual source upload with an approved external source connection and managed identity where appropriate.
  2. Replace overwrite with incremental ingestion, checkpoint/watermark and Delta MERGE logic.
  3. Add explicit schema enforcement, duplicate conflict handling, richer reject reasons, logging and alerts.
  4. Implement customer/product slowly changing dimensions where required; the lab uses simplified current-state dimensions.
  5. Configure schedule, retries, notifications, Git source control and promotion to test/prod environments.
  6. Record evidence: pipeline run status, table row counts, Gold sales total and Power BI screenshot.

Completion criteria: source CSV → Copy activity → Bronze table → Silver clean/quarantine tables → Gold star schema → Power BI report, all validated.
